# GGSAFE

Google로 로그인하고 본인 이메일과 비밀번호의 공개 유출 기록을 확인하는 한국어 보안 도우미예요. 기존 화면을 재사용하는 Streamlit 버전이에요.

> **현재 상태:** 앱 코드와 합성 데이터 검증은 준비됐어요. 공개 주소의 실제 Google 로그인과 영구 기록 보관 연결은 아직 확인 전이에요. 저장소 업로드가 배포 완료를 뜻하지는 않아요.

## Streamlit Community Cloud 연결

Streamlit에서 **Create app → GitHub 저장소 연결**을 선택하고 다음을 입력해요.

| 항목 | 값 |
|---|---|
| Repository | `hwnam0812/ggsafe` |
| Branch | `feat/streamlit-web` |
| Main file path | `streamlit_app.py` |
| Python | `3.11` 이상, `3.15` 미만 |

첫 업로드 대상 저장소는 비어 있었으며 공개 범위는 변경하지 않았어요. 기존 Windows 앱이나 Google 등록은 수정하지 않았어요.

### 로그인과 기록 보관 설정

1. Streamlit에서 사용할 앱 주소를 정해요. Google OAuth 웹 클라이언트의 승인된 리디렉션 URI에 `https://실제-앱-주소/oauth2callback`을 **추가**해요. 기존 PC·웹 주소는 지우지 않아요.
2. Streamlit 앱의 **Settings → Secrets**에 `.streamlit/secrets.example.toml`의 항목을 등록해요. Google 클라이언트 ID·비밀값, 충분히 긴 무작위 쿠키 비밀값, 실제 돌아올 주소, 영구 보관용 PostgreSQL 연결이 필요해요. 예시 문자열은 실제 값으로 바꿔야 해요.
3. Google 권한은 `openid email`만 사용해요. `expose_tokens`는 추가하지 않아요. 로그인 주소를 PC 내부 주소로 설정하지 않아요.
4. 공개 앱에서는 PostgreSQL을 반드시 연결해요. 연결이 없으면 오류를 안내하며, 사라지는 임시 파일로 조용히 바꿔 저장하지 않아요.
5. 새 창에서 공개 앱을 열고 실제 Google 로그인, 검사 동의, 검사 결과, 로그아웃·재접속, 다른 브라우저의 같은 계정 이력을 확인한 뒤 게시 완료로 판단해요.

실제 Secrets·쿠키·검사 기록·GitHub 토큰은 이 저장소에 포함하지 않아요. `GH_TOKEN`은 코드 업로드 도구에만 필요하고 게시 앱에는 필요하지 않아요.

## 개인정보와 검사

- Streamlit이 확인한 Google 계정만 사용해요. 로그인한 이메일 이외의 검사는 거절해요.
- 로그인은 기본 30일 쿠키를 사용해요. Google 비밀번호·메일함·Drive 권한은 가져오지 않아요.
- 이메일은 별도 동의와 클릭이 있을 때 XposedOrNot에 보내요. 이력 저장은 기본 꺼짐이에요.
- 비밀번호는 브라우저 안에서 변환하고 앞 5글자만 HIBP Pwned Passwords에 보내요. 비밀번호 원문과 전체 해시는 Python 앱에 보내거나 저장하지 않아요.
- 완료한 비밀번호 검사는 시각·결과·발견 횟수만 저장해요. 오류·중단 결과는 저장하지 않아요. 저장만 재시도할 때 외부 검사를 반복하거나 중복 기록을 만들지 않아요.
- 이력은 계정별 최근 30일·최신 100개예요. 유출 기록 미발견은 계정이 안전하다는 보장이 아니에요.

## 개발과 검증

공개 앱은 `streamlit_app.py`를 실행해요. 필요한 Python 패키지는 `requirements.txt`와 `pyproject.toml`에 있어요.

```sh
uv sync
uv run streamlit run streamlit_app.py
uv run pytest
npm ci
npm run build:streamlit
npm test
```

`ggsafe_streamlit/ui`는 Streamlit이 제공하는 필수 화면 패키지예요. 화면 소스를 수정할 때만 `npm run build:streamlit`으로 다시 만들어요. Community Cloud에서 Node 빌드를 실행할 필요는 없어요. 일반 웹 빌드 산출물·개인 기록·개발 환경은 포함하지 않아요.

`npm run dev`는 로컬 미리보기 전용 실행기예요. 기록은 명시적으로 별도 로컬 보관을 사용하며 공개 앱의 기록과 공유하지 않아요. Google 연결을 시험하려면 `GGSAFE_STREAMLIT_REDIRECT_URI`에 실제 등록된 주소가 필요해요. 비밀값은 환경 변수 또는 로컬 Secrets로만 전달해요.

원래 웹 버전의 실행은 `npm run dev:web`로 보존했어요. 기존 웹의 72시간 로그인 규칙과 기록은 새 Streamlit 버전의 30일 로그인·기록과 별개예요.

### 확인한 범위

Python 테스트 112개와 기존 웹 테스트 179개, TypeScript 검사 및 화면 패키지 빌드가 통과했어요. `tests_streamlit`의 브라우저 검사는 합성 쿠키·응답으로 1440·558·383px의 검사·검색·목록 이동·저장·재시도·계정 분리·삭제·로그아웃을 확인했어요. 만료·위조 쿠키·다른 탭 로그아웃과 진행 중 조회 중단도 확인했어요. 보관 연결 미설정·실패 안내와 이메일 저장 재시도의 계정 분리·만료·변조 차단도 검사해요.

합성 로그인 검사는 실제 Google 로그인 성공을 의미하지 않아요. 실제 사용자 이메일이나 비밀번호로 외부 검사를 실행하지 않았어요. 공개 PostgreSQL 연결과 공개 주소의 Google 로그인은 별도 확인이 필요해요.

### 휴대폰 스크롤과 이력 저장

- 로그인·대시보드·검사·이력·가이드는 모두 최대 430px의 휴대폰 전용 한 열 배치예요. 넓은 PC 창에서도 데스크톱 배치로 바뀌지 않아요. 세로 9:16을 기본으로 하되 높이를 고정하지 않으며 가로 16:9에서도 전체 내용을 스크롤할 수 있어요.
- 검사 이력은 네 항목을 기록 한 건 안에 카드형으로 표시해 가로로 밀지 않아도 읽을 수 있어요. 보관 연결 안내와 다시 확인 버튼도 휴대폰 폭에 맞고, 다시 확인에 실패하면 현재 상태를 알려 줘요.
- 앱 내용이 늘거나 줄면 화면 높이도 따라 바뀌어 휴대폰 브라우저에서 페이지 끝까지 스크롤할 수 있어요. 별도의 안쪽 스크롤은 사용하지 않아요.
- 이메일 이력 저장에 실패하면 현재 결과를 유지하고 **이메일 이력 저장 다시 시도**를 제공해요. 외부 검사를 반복하지 않고 같은 기록 한 건만 저장해요. 대기 중인 결과는 현재 로그인 연결에서 최대 30분·10개만 유지하며 새로고침·로그아웃·기록 삭제 후 복구를 보장하지 않아요. 이메일 원문·서비스 목록은 저장 대기 정보에도 넣지 않아요.
- 로그인 설정과 이력 보관 설정은 별개예요. Google 로그인이 되어도 보관 연결이 없거나 실패하면 검사를 시작할 수 없어요. 앱 화면에 보관 연결 안내가 표시돼요.
- 운영자는 Streamlit 앱의 **Settings → Secrets**에서 기존 Google 설정은 그대로 두고 아래의 보관 항목만 등록해요. `[storage]`가 이미 있으면 새로 중복해서 만들지 않고 그 안의 항목을 수정해요. 비밀번호나 연결 주소는 채팅·GitHub에 올리지 않아요.
- 설정을 저장한 뒤 **보관 연결 다시 확인**으로 확인할 수 있어요. 암호화된 연결이 실패해도 일회성 파일 저장으로 대신하지 않아요.

### 현재 GGSAFE 보관 공간 연결

이미 존재하던 Supabase의 `ggsafe` 프로젝트(`twvieqoistnrdvhfeeya`)를 연결 대상으로 확인했어요. 지역은 기존 `ap-southeast-2`를 유지하며 새 프로젝트를 만들거나 기존 비밀번호·Google 등록을 바꾸지 않아요. 앱에 호스트·사용자 이름을 미리 맞춰 두었으므로 아래에는 **프로젝트 생성 때 정한 DB 비밀번호**만 들어가요. Supabase 계정 로그인 비밀번호나 관리 연결 토큰이 아니에요.

```toml
[storage]
database_password = "기존 GGSAFE DB 비밀번호를 여기에 입력"
```

이미 정상적인 `database_url`을 등록한 경우에는 그대로 쓸 수 있고 그 값이 우선해요. 예시 `USER`, `PASSWORD`, `HOST`가 남은 주소는 실제 연결 주소가 아니므로 비밀번호 방식을 쓸 때는 해당 예시 항목을 지워요. `GGSAFE_DATABASE_PASSWORD` 환경 변수도 같은 연결을 지원해요. `SUPABASE_ACCESS_TOKEN`은 설정 작업에만 사용하며 공개 앱이 읽지 않아요.

공개 보관 준비는 `supabase/migrations/20261117000100_ggsafe_history.sql`과 앱이 같은 변경문을 사용해요. 네 표 모두 행 보호를 켜고 익명·브라우저용 계정의 접근 권한을 제거해요. Python에서 확인된 Google 계정으로만 이력을 처리하며 다른 로그인 방식을 추가하지 않아요. 공유 보관 연결에 맞게 자동 prepared statement를 끄고 암호화를 강제해요.

실제 보관 공간에서 `supabase/tests/ggsafe_storage_probe.sql`의 합성 저장·조회·중복 방지·권한 검사를 통과했어요. 기존 DB 비밀번호를 안전하게 입력받은 뒤에는 `tests_streamlit/postgres_probe.py`로 실제 앱과 같은 Python 연결·암호화·이메일/비밀번호 메타데이터 저장·중복 방지·계정별 조회·캐시·횟수 제한·동시 조회 잠금도 확인했어요. 시험 변경은 모두 되돌리고 새 연결에서 시험 기록 0개를 확인했으며 실제 사용자 기록은 조회하거나 삭제하지 않았어요.

이 실제 연결 검사는 `GGSAFE_RUN_POSTGRES_PROBE=1`일 때만 별도 실행하며 앱에서는 호출하지 않아요. 비밀번호·연결 주소·원문 오류는 출력하거나 파일로 남기지 않아요. 관리 연결 토큰 대신 앱 전용 비밀 설정을 사용해요. 이곳의 미리보기 환경 변수는 Streamlit 공개 앱에 자동 전달되지 않으므로 운영자가 공개 앱의 **Settings → Secrets**에 위 항목을 등록해야 해요. 공개 사이트의 실제 Google 로그인 이후 저장 성공은 아직 직접 확인하지 않았어요.

`tests_streamlit/mobile.e2e.mjs`는 합성 계정으로 320·360·390·558·1440px에서 휴대폰 전용 배치·실제 터치 스크롤·마지막 안내 도달·내용 높이 갱신·이메일 저장 재시도의 중복 방지·이력 카드·보관 연결 안내와 재확인을 검사해요. 세로 360×640(9:16)과 가로 회전 후 768×432(16:9)의 계정창 조작도 포함해요. 보관 오류 화면은 합성 응답으로 검증하며 공개 연결 설정을 바꾸지 않아요.

설정 참고: [Streamlit 사용자 로그인](https://docs.streamlit.io/develop/concepts/connections/authentication), [Community Cloud 배포](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app).
